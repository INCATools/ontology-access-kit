Where Ontology Similarity and Text-Embedding Similarity Disagree

For a sample of term pairs in each of several ontologies, we compare:

  • ontology similarity, computed from the terms’ ancestor closures:

    1. Jaccard over is_a ancestors;

    2. Jaccard over is_a + part_of ancestors;

    3. IC-weighted Jaccard (simGIC) over is_a + part_of, with information content (IC) computed from the ontology structure;

    4. the same, with IC computed from annotation frequency where an annotation corpus is available: HPO disease annotations for HP, human GO annotations for GO. MONDO and CL have no comparable corpus here, so they keep structural IC. This is the main measure used for the corners below.

  • text similarity: cosine similarity of the terms’ LLM embeddings, as served by OLS.

IC weighting matters because sharing a generic ancestor says little. Structural IC alone can be misleading: a grouping class with few subclasses (e.g. HP Constitutional symptom) looks specific to the ontology structure even though its descendants (fever, fatigue, …) are annotated to a large fraction of diseases. Annotation-frequency IC corrects this.

Most pairs fall along a common trend. The interesting cases are the corners, where ontology and text disagree:

  • ontology-similar, text-dissimilar: terms that are close in the hierarchy but described in different words;

  • text-similar, ontology-dissimilar: terms that read alike but are classified apart.

The vectors and measures used here are available through OAK’s EmbeddingProviderInterface (closure / closure_ic models, jaccard / weighted_jaccard metrics).

Sampling pairs

Purely random pairs are almost all unrelated, so they would pile up in one corner. To cover the whole range of ontology similarity, most pairs are sampled by picking a term, moving up to a random one of its is_a ancestors, then down to a random descendant of that ancestor. A smaller number of fully random pairs is added. Only terms from the ontology’s own namespace are used (no imported terms), obsolete terms are excluded, and for HP only terms under Phenotypic abnormality are used (no clinical modifiers, inheritance modes, etc).

[3]:

def sample_pairs(adapter, prefix, root=None, seed=0):
    rng = random.Random(seed)
    if root:
        candidates = adapter.descendants(root, predicates=[IS_A], reflexive=False)
    else:
        candidates = adapter.entities(filter_obsoletes=True, owl_type=OWL_CLASS)
    terms = sorted(t for t in candidates if t.startswith(prefix + ":"))
    term_set = set(terms)
    pairs = set()
    while len(pairs) < N_RELATED:
        a = rng.choice(terms)
        ancs = [x for x in adapter.ancestors(a, predicates=[IS_A], reflexive=False) if x in term_set]
        if not ancs:
            continue
        x = rng.choice(ancs)
        descs = [d for d in adapter.descendants(x, predicates=[IS_A], reflexive=False)
                 if d in term_set and d != a]
        if descs:
            pairs.add(tuple(sorted((a, rng.choice(descs)))))
    while len(pairs) < N_RELATED + N_RANDOM:
        a, b = rng.sample(terms, 2)
        pairs.add(tuple(sorted((a, b))))
    return sorted(pairs)

Annotation-frequency IC

For HP, each OMIM/Orphanet/DECIPHER disease in phenotype.hpoa is an annotated entity; for GO, each human gene product in goa_human.gaf. Annotations are propagated up the is_a + part_of closure. The IC of a term is -log2((n_t + 1) / (N + 1)), where n_t is the number of entities annotated to the term or its descendants and N is the number annotated to the root of the term’s own aspect, found by following is_a only (so each GO aspect is normalized separately, every root has IC 0, and GO molecular functions that are part_of a biological process are still normalized within molecular function). Terms with no annotations get log2(N + 1). Negated annotations (NOT) are excluded. The annotation files are cached locally with pystow, and their release dates are printed below; the specific pairs and numbers discussed at the end come from these releases.

import gzip
import io

import pystow

ANNOTATION_FILES = {
    "hp": ("https://github.com/obophenotype/human-phenotype-ontology/releases/latest/download/phenotype.hpoa",
           "phenotype.hpoa", "#", "#version:"),
    # the GO server rejects requests without a user agent
    "go": ("https://current.geneontology.org/annotations/goa_human.gaf.gz",
           "goa_human.gaf.gz", "!", "!date-generated:"),
}

def read_annotation_file(name):
    url, filename, comment_char, version_key = ANNOTATION_FILES[name]
    path = pystow.ensure("oaklib", "annotations", url=url, name=filename, download_kwargs={
        "backend": "requests", "headers": {"User-Agent": "oaklib"}, "progress_bar": False})
    opener = gzip.open if filename.endswith(".gz") else open
    with opener(path, "rt") as f:
        lines = f.read().splitlines()
    # header lines only occur at the top; skip exactly those
    n_header = next(i for i, line in enumerate(lines) if not line.startswith(comment_char))
    version = next((line.split(":", 1)[1].strip() for line in lines[:n_header]
                    if line.startswith(version_key)), "unknown")
    return lines[n_header:], version

def hp_annotations():
    lines, version = read_annotation_file("hp")
    df = pd.read_csv(io.StringIO("\n".join(lines)), sep="\t", dtype=str)
    df = df[(df.aspect == "P") & df.qualifier.isna()]
    return df.groupby("database_id").hpo_id.apply(set), version

def go_annotations():
    lines, version = read_annotation_file("go")
    df = pd.read_csv(io.StringIO("\n".join(lines)), sep="\t", header=None, dtype=str, usecols=[0, 1, 3, 4])
    df = df[~df[3].fillna("").str.contains("NOT")]
    df["entity"] = df[0] + ":" + df[1]
    return df.groupby("entity")[4].apply(set), version

ANNOTATION_SOURCES = {"hp": ("HPO disease annotations", hp_annotations),
                      "go": ("human GO annotations", go_annotations)}

def annotation_counts(adapter, profiles):
    ancestors, counts = {}, Counter()
    for terms in profiles:
        closure = set()
        for t in terms:
            if t not in ancestors:
                ancestors[t] = set(adapter.ancestors(t, predicates=PREDICATES, reflexive=True))
            closure |= ancestors[t]
        counts.update(closure)
    return counts

def annotation_ic(adapter, counts, terms):
    # IC relative to the root of the term's own aspect: the is_a ancestor with the most
    # annotations. (is_a only, because GO molecular functions can be part_of processes.)
    ic = {}
    for t in terms:
        root_count = max(counts.get(a, 0) for a in adapter.ancestors(t, predicates=[IS_A], reflexive=True))
        ic[t] = math.log2((root_count + 1) / (counts.get(t, 0) + 1))
    return ic

ann_counts = {}
for name, (label, load) in ANNOTATION_SOURCES.items():
    profiles, version = load()
    ann_counts[name] = annotation_counts(adapters[name][0], profiles)

hp_ic = annotation_ic(adapters["hp"][0], ann_counts["hp"], ["HP:0025142", "HP:0000118"])

Scoring

For each ontology, closure vectors for all sampled terms are computed in one call so that they share dimensions, then weighted by IC. In the annotation-IC vectors, the shared ancestor with the largest weight is the most informative common ancestor (MICA), listed in the tables to show where the ontology places the pair.

The structural-IC version of these vectors is available directly from the adapter:

onto.closure_embedding_predicates = [IS_A, PART_OF]
onto.embedding_similarity_matrix(terms, model="closure_ic")  # weighted Jaccard = simGIC

[5]:

from oaklib.utilities.embeddings.closure_embeddings import closure_embeddings

def jaccard(x, y):
    x, y = x > 0, y > 0
    return (x & y).sum() / (x | y).sum()

def weighted_jaccard(x, y):
    return np.minimum(x, y).sum() / np.maximum(x, y).sum()

def running_median(x, y, window=61):
    # expected y for each x: median of y over the `window` nearest points in x
    order = np.argsort(x.values, kind="stable")
    ys, fit, h = y.values[order], np.empty(len(x)), window // 2
    for i, j in enumerate(order):
        fit[j] = np.median(ys[max(0, i - h) : i + h + 1])
    # pairs with the same x get the same expected value, independent of row order
    return pd.Series(fit).groupby(x.values).transform("median").values

frames, micas = [], {}
for name, (onto, ols) in adapters.items():
    pairs = pair_sets[name]
    terms = sorted({t for p in pairs for t in p})
    ids1, _, C1 = closure_embeddings(onto, terms, predicates=[IS_A])
    ids2, vocab, C2 = closure_embeddings(onto, terms, predicates=PREDICATES)
    struct = dict(onto.information_content_scores(vocab, object_closure_predicates=PREDICATES))
    W_struct = C2 * np.array([struct.get(v, 0.0) for v in vocab])
    if name in ann_counts:
        ann = annotation_ic(onto, ann_counts[name], vocab)
        W_ann = C2 * np.array([ann[v] for v in vocab])
    else:
        W_ann = W_struct
    ix1, ix2 = {t: i for i, t in enumerate(ids1)}, {t: i for i, t in enumerate(ids2)}
    tids, T = ols.entity_embeddings(terms, model=MODEL)
    T = T / np.linalg.norm(T, axis=1, keepdims=True)
    tix = {t: i for i, t in enumerate(tids)}
    rows = []
    for a, b in pairs:
        if a not in tix or b not in tix:
            continue
        shared = np.minimum(W_ann[ix2[a]], W_ann[ix2[b]])
        micas[(a, b)] = vocab[int(shared.argmax())] if shared.max() > 0 else None
        rows.append({
            "ontology": name, "a": a, "b": b,
            "jaccard_isa": jaccard(C1[ix1[a]], C1[ix1[b]]),
            "jaccard_isa_partof": jaccard(C2[ix2[a]], C2[ix2[b]]),
            "simgic": weighted_jaccard(W_struct[ix2[a]], W_struct[ix2[b]]),
            "simgic_ann": weighted_jaccard(W_ann[ix2[a]], W_ann[ix2[b]]),
            "text_sim": float(T[tix[a]] @ T[tix[b]]),
        })
    df = pd.DataFrame(rows)
    df["expected_text"] = running_median(df[PRIMARY], df.text_sim)
    df["text_excess"] = df.text_sim - df.expected_text
    frames.append(df)
    print(f"{name}: {len(df)} pairs scored ({len(pairs) - len(df)} missing a text embedding)")
scores = pd.concat(frames, ignore_index=True)

Selecting the corners

Comparing percentile ranks of the two measures does not work well here: most pairs have ontology similarity near zero, so a weak ontology similarity can still rank high and a pair with little in common ends up in the “ontology-similar” corner. Instead:

  • ontology-similar, text-dissimilar: among pairs in the top quarter of ontology similarity, the 20 with the lowest text similarity;

  • text-similar, ontology-dissimilar: the 20 pairs whose text similarity most exceeds what is typical for their level of ontology similarity. “Expected” text similarity is the running median of text similarity over the 61 pairs nearest in ontology similarity (the grey line).

def corner_table(onto, sub, tag):
    ids = set(sub.a) | set(sub.b) | {micas[(r.a, r.b)] for r in sub.itertuples()} - {None}
    labels = dict(onto.labels(ids))
    out = []
    for k, r in enumerate(sub.itertuples(), 1):
        mica = micas[(r.a, r.b)]
        row = {
            "#": f"{tag}{k}",
            "term 1": f"{labels.get(r.a) or ''} ({r.a})",
            "term 2": f"{labels.get(r.b) or ''} ({r.b})",
            "text": round(r.text_sim, 2),
        }
        if tag == "T":
            row["expected text"] = round(r.expected_text, 2)
        row.update({
            "IC-Jaccard": round(r.simgic_ann, 2),
            "IC-Jaccard (structural)": round(r.simgic, 2),
            "Jaccard is_a": round(r.jaccard_isa, 2),
            "MICA": labels.get(mica, mica) if mica else "(none)",
        })
        out.append(row)
    return pd.DataFrame(out).set_index("#")

What the corners show

Measures. IC weighting improves agreement with text in every ontology, and annotation-frequency IC improves it further where it is available: HP 0.79 → 0.80 and GO 0.76 → 0.80 (Spearman ρ, structural → annotation IC). In the tables, “(none)” means the pair shares only ancestors with zero IC, i.e. only a root (annotation IC is normalized per root, so each GO aspect root has IC 0).

Ontology-similar, text-dissimilar.

  • HP: clinically related pairs whose wording differs, for example Jaw claudication / Absent superficial temporal artery pulse (both signs of giant cell arteritis), Light-chain paraproteinemia / Increased anti-dust mite IgE antibody level, Geophagia / Bulimia, and Torsade de pointes / Ventricular escape rhythm. With annotation IC, weak groupings such as Constitutional symptom (2.9 bits rather than 7.7) no longer make this list.

  • GO: pairs that share a specific function the names don’t reveal, such as two oxidoreductases acting on CH-OH groups (L-galactose dehydrogenase / prostaglandin F synthase) and late endosome / fusiform vesicle (both cytoplasmic vesicles), alongside processes joined at a mid-level grouping.

  • CL: mostly neurons, glia and immune cells. Many have taxonomy-style labels (Astro-NT NN_1 Slc36a2 astrocyte (Mmus), GPe-NDB-SI LHX6-LHX8-GBX1 GABA …) that give a text model little to work with, or are related by lineage that the name doesn’t state (melanophage / plasmacytoid dendritic cell: mononuclear phagocytes).

  • MONDO: this corner still contains broad groupings such as hereditary disease and inherited disease susceptibility (e.g. monosodium glutamate sensitivity / Lamb-Shaffer syndrome). MONDO has only structural IC here, so these broad classes are not discounted. An annotation-based IC for MONDO (for example from disease-gene or disease-phenotype associations) would be the natural fix.

Text-similar, ontology-dissimilar. In every ontology this corner is dominated by one pattern: systematic variants. These are terms built from the same template that differ in one slot. The text model sees near-duplicates; the ontology deliberately separates them along that axis.

  • HP: digit and phalanx terms (e.g. Sclerosis of the distal phalanx of the 2nd finger / … proximal phalanx of the 5th finger, text 0.92), and onset or progression qualifiers (Late-onset / Progressive proximal muscle weakness, 0.91).

  • GO: opposite regulation (negative regulation of dendritic spine development / positive regulation of dendritic spine morphogenesis, 0.83; also male germ cell proliferation and respiratory burst), and near-identical chemistry (symmetrical / asymmetrical dimethylarginine, 0.97; pentadecane / heptadecane biosynthesis; cyclin B2-CDK1 / cyclin B3-CDK2 complex).

  • MONDO: numbered genetic subtypes (intracranial berry aneurysm 8 / 9, dilated cardiomyopathy 1R / 1GG), species variants (mycosis fungoides, dog / domestic cat), and acute / chronic pairs.

  • CL: subtypes and developmental stages (type I / type II cell of adrenal medulla, 0.93; immature / mature dendritic cells; promonocyte / monocyte).

Some of these pairs are also fairly close in the ontology (for example the GO symmetrical / asymmetrical dimethylarginine pair, IC-Jaccard 0.79). They appear here because their text similarity is far above what is typical for their level of ontology similarity, not because the ontology considers them unrelated. The practical point is that cosine similarity of label embeddings treats a single changed word (a digit, a sign, a number, a species) as a small difference, even when it is the whole point of the distinction. A few pairs are better candidates for a missing link, such as HP Periorbital fullness / Lower eyelid edema (text 0.84, sharing only Abnormality of the periorbital region).

CL and ``part_of``. For CL, following part_of brings anatomical ancestors into the closure, and these can dilute similarity between cells of the same type in different tissues. For example, fibroblast of cardiac tissue / fibroblast of areolar connective tissue has is_a Jaccard 0.79 but IC-weighted Jaccard 0.20.

Caveats. 400 pairs per ontology; one text model (text-embedding-3-large via OLS, which embeds a fixed text per class); annotation IC only for HP and GO. The specific pairs and numbers above come from the HPO annotation release 2026-09-02 and the human GO annotation file generated 2026-05-21 (printed above); later releases will shift them somewhat. The annotation files are cached by pystow under ~/.data/oaklib/annotations; delete them (or pass force=True to pystow.ensure) to pick up a newer release. The text-similar corner depends on the running-median window. Vectors are cached locally, so changing MODEL, the sample sizes or the corner rules only fetches new terms from OLS.
